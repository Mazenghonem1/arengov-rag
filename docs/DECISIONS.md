## Batch 1: Scope, users, demo story, data source (2026-11-09)

Facts checked before deciding (2026-11-09):
- `u.ae` serves server-rendered HTML (HTTP 200). No `robots.txt` (404) and no `sitemap.xml` (404).
- `u.ae` URLs are hierarchical: `/en/information-and-services/<category>/<subtopic>`. The Arabic version is the same path with `/ar/`.
- `u.ae/en/Footer/Copyright`: content is TDRA property; "Any unauthorised use, reproduction or printing ... is strictly prohibited." Terms page says nothing about crawling.
- `hukoomi.gov.qa` returns 403 to plain HTTP clients (bot protection), including its sitemap and terms.

## Batch 2: Arabic/bilingual handling and retrieval pipeline (2026-11-09)

Assumption carried into batch 4: deploy on Hugging Face Spaces free CPU tier (2 vCPU, 16 GB RAM, Docker).

| # | Decision | Reason | Status |
|---|---|---|---|
| D15 | Language detection by script: Arabic-script letters ≥50% of all letters → `ar`, else `en`. Answer language = latest message's language (MSA for `ar`). UI switch "Answer in: Auto / العربية / English" overrides. | Two languages with different scripts; a 3-line heuristic beats a language-ID model; the switch covers edge cases. | ✅ |
| D16 | Arabic normalization for BM25 only (docs and queries), never for embedding input: strip diacritics U+064B–U+0652, U+0670 and tatweel U+0640; أ إ آ ٱ→ا; ى→ي; ة→ه; Persian ی ک→ي ك; Arabic-Indic digits ٠–٩ and ۰–۹→0–9; leave ؤ ئ unchanged. | Standard low-risk rules; embedding models are trained on raw text; fees and day counts use Arabic-Indic digits. | ✅ |
| D17 | BM25 hand-written (Okapi, k1=1.5, b=0.75) with a unit test against a hand-computed example. Tokenize: lowercase → split on non-letter/digit → per-token analyzer chosen by script. `snowballstemmer` for EN and AR; short EN stopword list; AR normalized before stemming. One index over both languages. Eval report includes normalization+stemming on/off ablation. | Writing BM25 yourself is the visible, explainable part; stemmers aren't worth writing; the ablation gives a README number. | ✅ |
| D18 | `page_id` = URL path with the `/en/` or `/ar/` prefix stripped, shared by both language versions; unpaired pages allowed. Eval gold labels are `page_id`s (either language counts as a hit). Citations link to the chunk's actual page plus an "also in العربية/English" link to the pair. No cross-pair chunk merging in v1. | Page-level gold is the only fair cross-lingual scoring; citing the real source keeps citation accuracy honest (u.ae disclaims translation accuracy). | ✅ |
| D19 | Cross-lingual retrieval relies only on multilingual dense embeddings; no query translation in v1; BM25 is same-language. Rewriter runs only when chat history exists and writes the standalone query in the user's language. Eval reports recall split by same-language vs cross-language. Bilingual query expansion is a stretch ablation. | Keeps retrieval LLM-free, so retrieval eval in CI is fast and free; the split shows how much the dense half carries cross-lingual retrieval. | ✅ |
| D20 | Cleaning: BeautifulSoup + lxml with a u.ae-specific main-content CSS selector, fixed in the crawl phase after inspecting 5 sample pages and covered by a fixture-HTML test. Drop nav, footer, breadcrumbs, feedback widgets, share bars, scripts. Output Markdown-like text keeping H1–H4, lists, links; tables flattened to `Header: value; Header: value` rows. Pages with <200 chars after cleaning are logged and skipped. | Site-specific selector is transparent and testable; generic extractors are black boxes and sometimes cut Arabic content. | ✅ |
| D21 | Chunking: split on H2/H3 sections; pack paragraphs to ≤400 tokens (bge-m3 tokenizer); only over-long sections split, with one paragraph of overlap. Chunk text starts with `<page title> > <H2> > <H3>` (embedded and BM25-indexed). Record: `chunk_id, page_id, url, lang, pair_url, title, heading_path, text, snapshot_id, category`. | Gov pages are already organized by heading; the header line fixes context-less chunks ("the fee is AED 300" for what?). | ✅ |
| D22 | Embeddings: `BAAI/bge-m3`, dense only, via `sentence-transformers`, normalized 1024-dim, fp32 CPU. Index built locally once, shipped as files. Fallback only if HF Spaces memory/latency fails: `intfloat/multilingual-e5-small`. | Best open, free, CPU-runnable Arabic/cross-lingual quality; fits a 16 GB host. | ✅ |
| D23 | No vector DB: `embeddings.npy` + `chunks.jsonl`, exact brute-force cosine search in NumPy. README explains why and when to switch (~1M+ vectors → FAISS/pgvector/Qdrant). | At ~5k vectors a DB is pure overhead; knowing when not to use one is the better interview answer. | ✅ |
| D24 | Retrieval: BM25 top-50 + dense top-50 → RRF (k=60) → top-20 → reranker → top-5 to LLM. All numbers in one `config.py`; no YAML config system. | RRF needs no score calibration and is 5 lines; 5×400 tokens fits free-tier LLM limits. | ✅ |
| D25 | Reranker: `BAAI/bge-reranker-v2-m3`, max_length 512, CPU. If measured p95 rerank latency on HF Spaces >3 s, rerank top-10 instead of top-20. Eval report includes with/without-reranker ablation. | Multilingual, Apache-2.0, same family as the embedder; the fallback is decided now so deploy needs no design call. | ✅ |
| D26 | Prompt: context as numbered blocks `[n] (lang, title, url)\n<text>`; system prompt requires context-only answers, `[n]` after every factual sentence, target language, and exactly `NO_ANSWER` when the context lacks the answer. Plain-text output; `[n]` parsed by regex → URLs; out-of-range markers removed and logged on the trace. Two-layer refusal: (a) top reranker score < τ → refuse without calling the LLM, τ chosen in the eval phase to maximize answerable-vs-unanswerable F1; (b) `NO_ANSWER` → localized refusal + 3 closest page links + disclaimer. | Plain text works with every LLM including small local ones; the gate saves cost and latency; picking τ from data shows the eval set at work. | ✅ |
